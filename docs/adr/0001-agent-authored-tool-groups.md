# 模型编写的工具分组写进插件全局配置

Status: accepted

模型在会话里重组待激活目录时，分组结果写进插件的全局配置 `groups`，而不是会话级覆盖层，也不是只出建议：只有落盘，组的描述替换成员描述这份目录瘦身才能长期兑现，配置页也能立刻看到并继续手改。同一决定把触发权留给用户——这个工具只在用户明确要求整理分组时调用，不设审批门，因为 `requireApproval` 的语义在完全权限下本就失效，拿它当保护是错觉。

## Considered Options

- **会话级覆盖层**：每次会话按需临时聚组，不动用户配置。否决理由：每轮重建、收益清零，还要新增一层目录覆盖机制。
- **只出建议，用户在配置页确认后落盘**：最安全。否决理由：要先做一块确认 UI，成本前置；而「只追加、不接管」的写入语义已经能兜住误写风险。

## Consequences

- 一次错误的分组会波及所有会话与其他 agent，保护只能落在写入语义（见 [ADR-0002](0002-incremental-group-writes.md)）与调用时机上。
- 配置文档从此是模型与用户共同编辑的共享物，配置页必须容忍「背后有人在改」。
