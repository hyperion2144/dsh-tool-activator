# 激活按工具名记账，不按条目标识符

Status: accepted

模型激活一组工具时，会话历史里记下这批工具各自的名字，启用判断取「条目标识符 ∪ 工具名」。原因是分组从此可变——用户在配置页改，模型也能用分组工具改——标识符会随分组消失或改名；只认标识符的话，「上一步还能调用的工具」会在下一步无声消失，而这正是用户没有任何理由预期的破坏。

## Considered Options

- **写分组前把当前已启用的工具固化记一次激活**：不改投影结构，但等于在会话事件流里造假账，且只在写入点生效、覆盖不到配置页的手工改组。
- **不处理**：把一次无害的配置编辑变成对进行中会话的破坏。

## Consequences

- `ActivationHistory` 多一个可选的工具名集合，投影 `stateVersion` 升到 2；旧缓存失配会从会话日志重算，但历史日志里没有工具名，所以老会话仍只能按标识符工作。
- 「这个条目被激活过」不再是判断依据，激活回执里「已激活」一类的提示要改成按工具名判定。
