# 工具目录以本插件自己的消息注入，不挂宿主运行时上下文

Status: accepted

宿主把所有插件的运行时上下文（`systemPrompt.context()`）合并成**一份快照**：所有贡献者的正文拼成一段文本，再与上次保留的快照逐字比较，变了就整份重发。本插件的工具目录一直挂在里面，于是别的插件改动上下文时，会带着我们这段一起重发；我们改一次目录，也会让别人的段落陪着重来一遍。

## 决策

目录改以本插件自己的 user 消息发布（`source.kind = 'tool-activator'`，`form = 'catalog'`），在 `agent/pre-step` 瀑布里进入本步的消息批次，由宿主照常落库。宿主没有按贡献者分别比较的公开通道，所以这件事只能换机制，不能换 API。

## Considered Options

- **继续挂在运行时上下文上，只把内容改短**：缩短内容只是把每次重发的代价变小，别人的上下文一变我们仍然被整份重发。
- **把目录写进 system prompt**：目录随激活状态变化，改写 system 节点会重写请求头、废掉提供方缓存的前缀，与本插件「激活不重写请求头」的约定冲突。
- **自己的消息 + 增量补丁**：只发「新增了哪个条目」需要模型自己跨消息保持状态，压缩过的历史里不可靠；整份重发是宿主运行时上下文与 `dsh-mnemon` 已有的做法。

## Consequences

- supersede 由本插件负责：内容不变就不发；新消息自带「取代先前目录」的说明，消息源上也标成一次替换。
- 模型手里有没有目录，以会话历史为准：压缩换掉了旧消息、或这一步没落库，下一步就重新发布。
- 恢复的会话带着重启前发布的目录，发布器先读会话历史，避免同一份目录发两遍。
- 已激活条目只留标识符与成员名单：工具描述已经在请求头的 schema 里，重复一遍只是白占上下文。
- 本插件不再依赖宿主的运行时上下文，因此宿主关闭运行时上下文时插件照常工作。
- 投递依赖宿主的 `agent/pre-step` 瀑布（0.2.0-rc.2 起提供，本插件的 peer 下限已包含）；宿主若从不派发这一步，插件会打印明确告警而不是静默半工作。
