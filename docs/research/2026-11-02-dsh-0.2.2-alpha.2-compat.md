# 初查：dsh 0.2.2-alpha.2 兼容性

日期：2026-11-02（Asia/Shanghai）。范围：源码与本地环境证据，不含真实 GUI 端到端复现。

## 问题

报告人反馈：本插件配合 DSH `0.2.2-alpha.2` 使用时（1）配置页无法新增分组，提示宿主拒绝；（2）安装插件后会话直接报错「不存在 filter」。

## 结论（已确认）

**症状 2 已定性**：`0.2.2-alpha.2` 把 `system-prompt/assemble` 瀑布的入参改成了不含 `tools` 的 `PromptPresentation`，本插件在瀑布里直接解引用 `assembly.tools`，会话因此崩溃。

**症状 1 已定性（本仓客户端缺陷）**：点击「添加分组」会把 `{ identifier: '', name: '', description: '', tools: [], sections: [] }` 草稿立即写入 Host；`Config.groups[].identifier` 是 `Schema.string().pattern(/^[\w.-]+$/u).required()`，空串不匹配，Host 拒绝整段写入 → 乐观回滚（分组「闪一下」）+ 固定文案。实测 schemastery 3.18.4：`''` 与 `'has space'` 均被拒，整段文档报 `$.groups[0].identifier expect string to match regexp /^[\w.-]+$/u`。该缺陷与 0.2.2 的 API 变更无关（开关写合法值故能保存，与报告人观察一致）。

## 证据

### 版本基线

- 本仓库声明的 peer 范围为 `@deepseek-ai/dsh >= 0.2.0-rc.2`（`package.json:66`）。
- 开发依赖的 dsh 全套包固定为 `0.2.0-rc.2`（`pnpm-workspace.yaml` 的 catalog `dsh` 段）。
- 最近一次真实验证记录基于 `0.2.0-rc.2`；`0.2.1-alpha.2` 仅做过公开声明与兼容加载器的静态交叉核对（`docs/verification.md`，含「未执行 Build / 真实 GUI E2E」的限制说明）。
- 本机 `dsh --version` 输出 `0.2.2-alpha.2`（`/usr/local/bin/dsh` → 桌面应用内置 CLI），与报告版本一致。

### 症状 1：配置页新增分组被宿主拒绝

「宿主拒绝了本次修改。」这句文案在本仓库只有一处产生：

- `src/client/configuration-page.tsx:135-138`：`configScope.mutate([{ op: 'set', path: [field], value }], revision)` 返回假值时，回滚并提示该文案。

由此可确定：失败点在宿主对配置写入（`groups` 字段）的受理/校验，而不是前端表单或分组编辑器本身。编辑器一侧只有标识符格式与重复校验（`src/client/groups-editor.tsx:130-131`），与「宿主拒绝」不是同一条路径。

### 症状 2：会话报「不存在 filter」

- 在 `src/` 全量检索 `filter:` 无命中，说明本插件没有把 `filter` 作为配置键或 API 参数使用；该报错更可能来自宿主运行时或其依赖，需要完整报错文本才能定位。
- `filter` 在本仓库只作为数组方法出现（如 `src/prompt.ts`、`src/catalog.ts`），与上述文案不符。

### 症状 2 的根因证据（版本对比）

对比 npm 上 `@deepseek-ai/dsh-system-prompt` 两个版本的 `assemble()`：

- **0.2.0-rc.2**：`const assembly = { sections, contexts, tools: orderTools(...), variables }` 之后才 `ctx.waterfall('system-prompt/assemble', assembly, ...)` —— 瀑布入参含 `tools`。
- **0.2.2-alpha.2**：`const assembly = { sections, contexts, variables }` → 瀑布 → 之后才 `return { ...transformed, tools, sections, contexts }`；类型上 `PromptAssembly = PromptPresentation & { tools: ToolSchema[] }`，事件文档写明「tool declarations remain provider-owned」。

本插件 `src/prompt.ts:73-75` 的两条分支分别解引用 `assembly.tools`：`deferDeclarations` 为真时进入 `deferredToolSchemas()` 的 `tools.map(...)`（`src/prompt.ts:95`）→ `reading 'map'`；为假时 `assembly.tools.filter(...)` → `reading 'filter'`。分支由当前路由是否声明支持 `toolUpdate` 决定，故同一版本出现两种文案。

**影响**：即使补上空值保护，过滤也不再生效 —— 0.2.2 用 provider 收集的 `tools` 覆盖瀑布返回值（`{ ...transformed, tools }`），隐藏策略必须迁移到 provider 级入口（注册期 `deferLoading`）或由插件自持注册。
